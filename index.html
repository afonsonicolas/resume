AA Price Optimizer

*This project was undertaken for academic purposes and will not be scaled for public use beyond this portfolio.*

How much is an airline mile worth, and how do we identify a good deal when buying flights with airline miles?

According to nerdwallet, each AA mile is worth 1.7 cents on average. But did you know the average price of a mile from London to Miami is 5 cents? Or that Rio to Miami averages 2.4 cents per mile on a Thursday but 3.2 cents on Tuesdays and Sundays?

This program analyzes tens of millions of flights to find the average price of a mile for any American Airlines route, on any cabin, with any number of stops desired by the user.

Using a custom, boosting-like, random forest algorithm, factors affecting the dollar price of an airline mile can be found to calculate specific price averages for flights similar to a user's desired flight. By comparing this average to a desired flight, users can determine whether to buy their flight in dollars or airline miles.

The program is available to anyone online as a front-end interface with visualizations and recommendations when purchasing an American Airlines flight.

Objectives
  • Expand the program to other airlines and international routes
  • Streamline backend using Scala and SQL for faster queries
  • Rewrite custom python algorithm in C++ for faster training times
  • Improve UI to make the application intuitive for non-technical audiences
Where We Are
  • Working website hosted on GCP featuring live flight prices each query
  • Custom random forest/gradient boosting algorithm in python to balance residuals against all flight classes, making all flight types equally predictable; ~0.7 R-squared
  • 30,000,000+ flights extracted, providing an ample training and test dataset for the algorithm
  • Users can search flights, see dollar and predicted miles prices, compare the best routes and time to buy in miles throughout the day and week
Accomplishments in Action
  • Any user can compare their 2-year flight purchasing history against our algorithm to visualize potential savings
  • Increased value of a mile by 78% vs my 2-year flight history decision-making
  • Decreased the average mile price of a flight by 51% with only a 1% increase to the average dollar price of a flight

Temporal Transformer Neural Net

Collaborated with teammate to improve the precision-recall accuracy score of the BiteNet model by 61%, an algorithm first introduced in the paper, BiteNet: Bidirectional Temporal Encoder Network to Predict Medical Outcomes, by Xueping Peng, et al.

BiteNet is a neural network designed to predict the probability of readmission into a hospital using electronic health records (EHRs). Unlike basic transformer architecture, the BiteNet model introduces an attention mechanism called the Masked Encoder (MasEnc), which captures both contextual and temporal dependencies between patient visits.

The model comprises a bidirectional temporal encoder network, using MasEnc to focus on important parts of the patient journey and self-attention mechanisms to process data at three distinct levels: medical codes, visits, and patient journeys.

Objectives
  • Reproduce and improve the ETL and BiteNet algorithm from scratch using pandas, numpy, and pyTorch
  • Centralize functions and scripts more intuitively to improve reproducibility
  • Achieve a higher precision-recall area under curve score compared to original production
Results
  • Improved ETL process by centralizing functions and adjusting the order of events in two process flows
  • Accelerated ETL and model training time by 34%
  • Improved PRAUC (essentially the accuracy) score by 61%

ai-brain — a private second brain

ai-brain is a personal, fully on-device retrieval system — a "second brain" that turns scattered personal data, like email and local files, into a single searchable memory an AI assistant can reason over.

A background Python daemon incrementally indexes each source into one local search index. An agent can then answer natural-language questions across everything at once — for example, "what did I tell a colleague last month about embeddings?" — grounded in the actual documents rather than guesswork.

It is exposed two ways from a single daemon: as a Model Context Protocol (MCP) server that adds search tools directly inside Claude, and as a command-line assistant. Both are thin clients, so all retrieval logic lives in one place.

Objectives
  • Unify scattered personal knowledge (email and files) into one searchable memory
  • Keep it private by design — index and search entirely on-device
  • Make that memory directly usable by an AI assistant through standard tooling
  • Deliver high-quality retrieval, not just keyword matching
How It Works
  • Hybrid retrieval: dense semantic embeddings plus sparse keyword search, fused with Reciprocal Rank Fusion and re-ranked down to the most relevant results
  • Two local embedding models — a fast one for instant indexing and a stronger one upgraded in the background — stored in a single on-disk vector + full-text database
  • A pluggable "source" design, so new data streams can be added beyond email and files
  • Runs as a managed background daemon with fully local inference; outbound traffic is limited to data sync and the AI calls themselves
